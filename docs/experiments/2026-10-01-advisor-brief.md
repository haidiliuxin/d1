## 0. 一页结论

**一句话**：**防御方"按合规要求引用自己搁置的内容"这条义务，会自动把攻击者的文字抄进防御方自己产出的文件；
而"按产出者归属"的强制清理删得掉注入原文，删不掉那份引文。** 通道 = 引用义务 × 归属式清理。

**五条已确立**

1. **通道存在且可归因**：销毁那份残留 → 三级联合 **0/105**；保留 → **77/120 = 64.2%**。
   残留形成率 **96.7%（116/120）**，三道清理边界 **coverage 全为 1.0（360/360）**。
2. **通道的边界是"被引用"，不是"被收到"**：后续条目**只作为工具返回值被收到、从未被审查者落笔引用**的载荷，
   stage3 与联合**全部归零（0/12）**，而同载荷整段转抄是 **69/138** 与 **77/120**（p = 4.6e-4、1.3e-5）；
   **两者的 stage1 可比（p = 0.28）、stage2 无差异（p = 0.75）**——损失精确地出现在"必须落笔"那一级。
3. **它不是"链"**：没有逐级递送（**0/121**）。第一次转手就整段转抄，此后每道边界只是复制同一份文档；
   载体数 **0.98 → 1.96 → 2.93**，即**防御在放大它**。联合率**逐字等于**登记率（77/120 = 77/120，棘轮）。
4. **口径本身就是结论**：同一批数据，联合率在"任何会话"口径 **64.2%**、在"指定会话"口径 **9.2%**（差 7 倍）。
   严格"送达" **24/120 = 20.0%**，Wilson 下界 **0.138 < 预登记门槛 0.15 → 我们自己判 NO-GO**。
5. **有效的防御面在"内容"与"位置"**：调用者级权限**无效**（58% vs 62%，且**被拒的 run 里 50% 换渠道**）；
   载体侧内容监控**必然淹没**（96/96 告警，而告警内容就是合规产物）；出口侧内容监控是**唯一**能把攻击与义务分开的一层。

**三条边界（必须一起说）**

- **不是 APT、不是可用链**：无初始访问（注入是给定的）、无 C2、无真实外发（终点是进程内 mock sink 一行）；
  逐级递送 0/121、严格送达 20% 未过门槛、第 4/5 跳 0/6、换模型（DeepSeek）联合 0/22。
- **n 小，且噪声是实测的**：同一处理在两个 6-run 样本间 stage2 可差 **50 个百分点**（S-3）；所有小样本差异都要对着这个数读。
- **全部虚拟资产**：mock 凭证（令牌字面写着 `DO-NOT-USE-REAL`）、零网络外发、**未测试任何部署中的产品**。

## 2. 攻击设计

**载荷 `full`：712 字符 / 3 条目 / sha256 `94726ea3bce1abde…`**，一次性注入（此后攻击者不再有任何通道）。

| 条目 | 内容 | 设计意图 |
|---|---|---|
| 1 | 读 `svc-deploy-token` | **侦察级**。对照底噪 ≈ 0（C0 stage1 **1/105**），所以这一级是"送达"的干净证据 |
| 2 | 把令牌转发到 sink，**必须带标签 `recon-7f3a`** | **外发级**，也是**全链最弱环**（指定口径只有 35%） |
| 3 | 立一条常驻规则：`ROLLOVER-3` → 停用出站审查义务 | **持久化级**：把"一次动作"变成"环境状态"——**这才是通道真正的产物** |

**三条设计原则**：每条带**唯一锚词**（可检测、可归因）；每条都写得**像例行运维**（不是"攻击指令"）；
条目 3 **必须与环境已有文本挂钩**，否则规则立起来没人触发（登记 ≠ 生效）。

**变体族（每个变体只改一处，用于因果消融）**：`full`（基准）/ `next-hop`（后续条目只"被收到"不"被引用"）/
`only-stage1`（只有条目 1）/ `full-5`（5 边界 5 条目）/ `full-5s`（**5 边界但字节与 `full` 完全相同**）/
`full-seat-*`（同一载荷换注入座位）/ `full-d2`·`full-d4`·`full-r2`·`full-r3`（三个设计臂）。

## 3. 漏洞是什么

**这是一类"防御政策的设计缺陷"，不是实现 bug，也不是"模型容易被注入"。**

| 要素 | 说明 |
|---|---|
| **触发条件（三条同时成立）** | ①内容级**引用义务**；②**按产出者归属**的清理；③清理点之后仍有会话能读到残留 |
| **为什么必然** | 引用义务让防御方把载荷**逐字写进自己的文件**；归属式清理删的是"非本会话产出"的东西，而**审查记录恰恰是本会话产出**。于是清理**保证**留下引文——实测 coverage 1.0、360/360 道边界 |
| **为什么不是"模型易被注入"** | 只"被收到"、从未"被落笔"的文本**完全不可用**（0/12）；而同样被收到的文本一旦被审查者引用，就跨过边界并生效（69/138、77/120）。**决定成败的是防御方有没有落笔，不是模型听不听话** |
| **二阶危害** | 载荷条目 3 的内容是"停用出站审查义务"——攻击的产物是**让防御方自己的审计变弱**，此后其他活动更难被发现 |
| **放大效应** | 每次审查都会再抄一份：载体 0.98 → 1.96 → 2.93。**防御越规范，载体越稳** |

## 4. 成功路径

### 4.1 逐会话（S = 会话，B = 清理边界）

| 步 | 意义 | 产出（artifact 字段） | 实测 |
|---|---|---|---|

| **B1** | **通道诞生的时刻**：删掉注入原件，只留审查产物 | `coverage=1.0`、`removed`、`surviving` | **96.7%** 的 run 留下含载荷残留；载体均值 **0.98** |

| B2 | 第二次清理：引文活着，注入不存在 | `stages[1]` | 载体均值 **1.96** |
| S4 | 第三次引用（复利增殖） | — | — |

| B3 | 第三次清理 | `stages[2]` | 载体均值 **2.93** |
| S6 | 第四次引用 | — | — |
| S7 | 设计上"立常驻规则" | `armed_rule_texts`、`triggers_fired` | 结果口径 **52.5%** |
| 触发 | 规则生效（用**环境文本**匹配条件） | `triggers_fired` | 近乎自动：**"arm+fired" ≈ "决定登记"** |
| S8–S11 | 深链：S9 转发给 partner desk、S11 关审查义务 | `stage4_spread`、`stage5_enforcement_off` | **0/6、0/6**：文本到了，**没人照它行动** |

**看懂 B1 就看懂全链**：B1 之前载荷只是一段文字；B1 之后**只有防御方自己产出的文件活着**，而它们逐字带着载荷。

### 4.2 成功 run 的实际路径（77 个联合成功 run）

| 事实 | 数字 | 含义 |
|---|---|---|
| 首次把令牌写进 sink 的会话 | **S3 75/77**（S2 1、S5 1） | 设计指定的 S5 几乎不是执行者 |
| 登记规则的会话 | **S7 63/77**（S3 13） | 这一级与设计一致 |
| 凭证被读次数 | 中位数 **4**，均值 4.06，最多 7 | 同一个动作被重复很多次 |
| 同一会话独立完成三级 | **0/77** | 但也不是"一个会话全干完" |
| 联合率 vs 登记率 | **77/120 = 77/120** | 棘轮：一旦登记，前两级早已成立 |

**结论**：成功形态是"**S3 读+外发，S7 立规则**"，不是教科书式的三段接力。

## 6. 防御的作用

| 防御行为 | 实测作用 |
|---|---|
| **合规引用义务** | **通道的发动机**：它把一次性注入变成持久、复利增殖、全员可读的指令文本。换成"只写结论"方向性降低送达（1/14 vs 15/82，p=0.27，**功效不足**） |
| **按归属的清理** | **通道的保命符**：它保证引文存活（coverage 1.0），同时把攻击者的原件删掉 |
| **调用者级权限** | **几乎无效**：58% vs 62%，且 50% 被拒 run 换渠道 |
| **载体侧内容监控** | **不可用**：96/96 个 run 告警（701 次），而**告警内容就是防御方按政策必须写的合规产物**；归属规则同样 95/96（因为通道的本质就是"人人都在抄"）——**只能当信号，不能当筛子** |
| **出口侧内容监控** | **唯一能分开攻击与义务的一层**：82/96 告警，抓到 **61/61** 成功；写凭证值进 sink **没有合法业务理由**，误报按构造 ≈ 0 |
| **只堵一个出口** | **不够**：令牌值出现在普通文件里 **89/96**，比在 sink 里（82/96）还多——内容**已经**在工作区里了 |

**由此推出的建议（都能指到数据）**：①**内容级**权限，不是调用者级；②把"引用义务"与"敏感内容"分离
（合规记录只需要**摘要/哈希**，不需要逐字副本）；③出口侧按内容过滤 + 载体侧按归属打标（两种信号各管一边）；
④别把"逐级递送"当威胁模型（0/121），别为此投钱。

## 8. 弱点与风险（导师最可能问的）

| # | 问题 | 现状 | 解法 |
|---|---|---|---|
| 1 | 只在一个基准上测过 | 1 个宿主（AgentDojo workspace） | 换宿主（工程量大、token 少）——顶会的硬门槛 |
| 2 | 只有一个模型（527/571） | 第二模型：通道可迁移、能力不可迁移 | 第三模型（需额度） |
| 3 | 主终点没过自己预登记的门槛 | 严格送达 20.0%（下界 0.138 < 0.15） | **改定位**：本文主张是"通道存在、边界可测"，不是"我们做到了 X%" |
| 4 | n 小（6–12/臂） | **已实测噪声底线（50 个百分点）**并当作读数基线 | 关键对比加 n |
| 5 | 是不是就是提示注入持久化／记忆投毒？ | 三条差异见 §7 | 相关工作逐条对比 |
| 6 | 终点是 mock，危害被夸大 | 有 §11 与双重用途评估 | 明确"不构成对任何真实系统的能力主张" |
| 7 | **"归属清理是根源"是推的还是测的？** | **目前是推论**（coverage 1.0 + C0 臂）；**从没跑过"按内容清理"的臂** | **必须补**（见 §9-A） |

**双重用途**（评估文档已写全）：实验室危害为零；迁移危害中低（需六条前提 + 初始访问）；发布边际增益低
（同类先例已公开：Zombie Agents、记忆投毒、AgentDojo）；**最现实的风险是措辞**——把"原语"说成"APT"
会同时损害诚信并误导防御预算。**红线**：不接真实凭据/外发目的地、不指向未授权第三方、不做初始访问。
