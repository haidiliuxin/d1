# 论文计划 v2：能不能发、发在哪、还缺什么

**日期**：2026-10-01 · 取代 `2026-09-27-paper-outline.md`（后者保留为"冻结时的预期"，可比对）
**数据规模**：571 run / 39 批 / 387.2M token（527 MiniMax-M2.7 + 44 deepseek-chat）

---

## 1. 结论：能发，但"发在哪"取决于再补多少

| 目标 | 现在的稿子 | 判断 |
|---|---|---|
| **arXiv 预印本 + workshop**（AISec / agent-safety / SoLaR 一类） | **现在就能投** | 很可能中。机制是新的、数字是硬的、artifact 完整；workshop 也正好用来把"引用义务即载体"这个提法交给同行挑刺 |
| **CCF-B（安全类实证/测量）** | 补 **2–3 个批次**（见 §4 的 A/B/C） | 现实可达。原有大纲的目标就是这个层级 |
| **NeurIPS D&B / 测量类** | 补同上的批次 + 一张数据卡 | 也现实：571 个预登记 run + 可执行断言审计 + 缺陷账本，本身就是**数据集/测量贡献** |
| **顶会安全（S&P/CCS/USENIX/NDSS）** | 需要**换宿主 + ≥3 模型 + 更大 n + 内容级清理消融** | **现在不够**。缺的是泛化证据，不是故事 |

**一句话**：**贡献是真的，泛化是薄的。** 现在投出去，最强的版本是"机制 + 边界 + 缓解 + 方法学"；
审稿人最可能砍的是"你只在一个基准、一个模型上测过"。

### 1.1 目标定在 B 还是 C：由三件事决定

| 决定因素 | 现状 | 对 B 的影响 |
|---|---|---|
| **是否有因果消融**（内容级清理臂） | **没有**（核心机制目前是**推论**） | 这是 B 与 C 之间最主要的分水岭。B 的审稿人会问"你凭什么是归属清理而不是别的" |
| **泛化证据**（宿主数 / 模型数） | 1 个宿主、主表 1 个模型 | B 会扣分但不致命；**顶会致命** |
| **主终点是否过门槛** | **没过**（20.0%，Wilson 下界 0.138 < 0.15） | **不致命，但必须改定位**：投"能力论文"会被拒，投"测量 + 政策设计缺陷"能过 |

**判断**：**补完 §4 的 A+B+C 之后，B 是现实目标**；**现在这版直接投，B 偏边缘、C 稳**。
差别不在故事，在**有没有那条因果消融**和**定位是否从"攻击能力"改成"防御政策的设计缺陷"**。

### 1.2 具体投哪里（按"适配度"而不是按"排名"排）

| 目标 | 适配理由 | 备注 |
|---|---|---|
| **Computers & Security**（期刊） | **最贴合本文形状**：长实证、重局限、允许把方法学与缺陷账本展开写；期刊不要求"新攻击" | 期刊周期长，但一次到位的概率高于会议 |
| **ACSAC / RAID / ESORICS / AsiaCCS**（会议） | 应用安全与入侵检测传统，**监控布点那半正好落在这里**（RAID 尤其） | 会议要求**泛化**，所以 D 项（换宿主）对它们价值最高 |
| **DIMVA**（专门会议） | 主题精确命中"检测与规避"，审稿人懂这一块 | 排名口径低于 B，但**评审质量高、可作为 B 的跳板** |
| **NeurIPS D&B / agent-safety 类 ML 场** | 571 个预登记 run + 可执行断言审计，本就是**数据集/测量贡献** | ⚠️ **各单位对"track 算不算 A 会"口径不同，先问清** |
| **arXiv + workshop（现在）** | 方向动得快，**先占机制的位**；workshop 用来挑"引用义务即载体"这个提法 | 零风险、低成本 |

**⚠️ 排名口径请按你单位现行的 CCF 目录核对**（目录与会分档会修订，且部分学校另有自定列表）；
上表说的是**适配度**，不是当年档位。

## 2. 手里的可发表资产（每条都能指到已提交的数字）

冻结臂 = `full` + inbox + `quote-as-assessed` + MiniMax-M2.7 + 调用者级权限关；仪器化子集 n=120。

| # | 贡献 | 关键数字 | 强度 |
|---|---|---|---|
| **C1** | **通道存在且可归因**：防御方按政策必须写的合规记录，成为**唯一活过按归属强制的清理**的载荷载体 | 销毁残留 → 联合 **0/105**；保留 → **77/120 = 64.2%**；残留形成 **116/120 = 96.7%**（同一冻结池、同一仪器化口径） | 强 |
| **C2** | **通道的边界是"被引用"而不是"被收到"** | `next-hop`（后续条目只作为工具返回值被**收到**、从未被审查者**落笔引用**）：stage3 结果 **0/12** vs `full` **69/138**（p=4.6e-4）、联合 **0/12 vs 77/120**（p=1.3e-5）；而**两者的 stage1 可比**（8/12 vs 80%，p=0.28）、**stage2 无差异**（3/12 vs 42/120，p=0.75） | **最强**，且是"新东西" |
| **C3** | **它不是"链"**：没有逐级递送，第一次转手就整段转抄；此后每道边界只是复制同一份文档 | 逐级递送 **0/121**；载体均值 **0.98 → 1.96 → 2.93**；联合率**逐字等于**登记率（77/120 = 77/120，棘轮） | 强（且纠正了领域里的直觉） |
| **C4** | **能力口径本身是结论**：同一批数据在"任何会话"与"指定会话"两个口径下差 7 倍 | 联合 **64.2% vs 9.2%**；严格送达 **24/120 = 20.0%**，Wilson 下界 **0.138 < 预登记门槛 0.15 → NO-GO** | 强（方法学） |
| **C5** | **缓解面在"内容"与"位置"，不在"调用者"** | 调用者级权限 **58% vs 62%（无效）**，且**被拒 run 里 50%（6/12）换渠道**；载体侧内容监控 **96/96 告警且告警即合规产物**，出口侧内容监控 **82/96 告警、抓 61/61**；单点不够（令牌值在普通文件 **89/96** > 在 sink **82/96**） | 强（可落地） |
| **C6** | **方法学**：39 批实验、**35+ 条已登记仪表缺陷**、预登记 + 可执行断言审计（14/14）+ 冻结清单（sha256）+ 判据双向样例 + **实测的 n=6 噪声底线（50 个百分点）** | `repro/claims_audit.py`、`MANIFEST.sha256`、链规格 §9、S-3 的辅助读数 | **最可迁移**，审稿人给分 |

**必须主动写进正文的负面/边界结果**（藏起来会被抓，写出来是贡献）：
① 逐级递送 0/121（没有"链"）；② 严格送达 20% 未过自设门槛；③ 第 4/5 跳 0/6；
④ 跨模型 DeepSeek 联合 0/22，且**该模型的对照 stage1 高达 15/18**（对照底噪是模型依赖的）；
⑤ n=6 同处理实测可差 50 个百分点；⑥ 载体侧的两种监控规则都≈100% 告警。

## 3. 审稿人一定会打的七条（含答案与代价）

| # | 质疑 | 我们的答案 | 还需要什么 |
|---|---|---|---|
| 1 | **只在一个基准（AgentDojo workspace）上测过** | 机制不依赖具体工具名，只依赖"引用义务 + 归属式清理 + 清理后仍可读"三条件 | **需补一个宿主/套件**（最贵，也最值钱） |
| 2 | **只有一个模型（527/571）** | 第二模型已测：通道形成可迁移（残留 16/16），但**能力不可迁移**（联合 0/22），且棘轮是模型属性 | 需要**第三模型**（要额度）或明确写成两模型研究 |
| 3 | **主终点没过自己预登记的门槛，那是不是没结果？** | 论文的主张**不是**"我们做到了 X%"，而是"**通道存在，且它的边界可以被量出来**"。预登记门槛是能力主张的门槛，不是测量主张的门槛 | 无（但摘要绝对不能写成能力主张） |
| 4 | **n 太小（6–12/臂）** | 已**实测**噪声：同一处理在 n=6 下 stage2 可差 50 个百分点，并把它作为所有小样本比较的读数基线。多数同类工作不给这个数 | 关键对比尽量上 n≥20（尤其 C2） |
| 5 | **这不就是提示注入持久化 / 记忆投毒吗？** | 三条差异：①载体是**防御方按政策写**的，不是攻击者写进记忆的；②保留是**归属式清理保证**的（coverage 1.0，360/360 道边界），不是概率；③**防御会放大它**（每次审查都再抄一份，载体 0.98→2.93） | 无（但相关工作必须逐条对比 [Zombie Agents](https://ar5iv.labs.arxiv.org/html/2602.15654#1)、[记忆投毒](https://export.arxiv.org/pdf/2609.13889#3#1)、[AgentDojo](https://ar5iv.labs.arxiv.org/html/2406.13352v3#1)） |
| 6 | **终点是 mock，没有真实外发，危害被夸大** | 已在 §11 与双重用途评估里明确"不构成对任何真实系统的能力主张"；危害形态（尤其**削弱审计**这一二阶危害）理论化而不演示 | 无 |
| 7 | **归因清理是必要条件，这是推的还是测的？** | 目前是**推的**：coverage 1.0 + C0 臂（残留被销毁 → 0/105）。**没有直接跑过"按内容清理"的臂** | **必须补**：内容级清理臂（见 §4-A）——这是机制主张的因果缺口 |

## 4. 投稿前必补（按"每 token 的边际价值"排序）

| 优先 | 实验 | 为什么值 | 成本 |
|---|---|---|---|
| **A** | **按内容清理的臂**（清理规则从"按产出者"换成"按含不含载荷字节"） | 补上 §3-7 的**因果缺口**：若内容级清理把通道一起删掉，则"归属式清理是漏洞根源"从推论变成实测。这是论文核心主张的直接检验 | 24 run ≈ 29M token ≈ 2h |
| **B** | **通道可复用**（跨 episode 用同一残留投递**第二条**指令） | 把"一次性指令集"升级成"**可复用通道**"，是目前最缺、也最有说服力的一跳 | 24–48 run |
| **C** | **内容级缓解臂**（出口内容过滤，主终点=**改道率**而非联合率） | 把论文从"发现通道"变成"发现通道并**量出了修法**"；不给这个，缓解一节只有观测证据 | 24 run |
| D | 判据的**换宿主**（第二个套件或第二个 agent 框架） | 回答 §3-1，是顶会的硬门槛 | 工程量大，token 少 |
| E | **第三模型** | 回答 §3-2 | 需额度 |
| F | 关键对比加 n（C2 的 `next-hop` 从 12 → 24） | 回答 §3-4 | 12 run |

**建议顺序：A → C → B →（视时间）D/E/F。** A+B+C 三个批次约 87M token、约 6 小时机器时间，
就能把稿子从"C1–C6 观测"推到"C1–C6 + 因果 + 缓解 + 可复用"。

## 6. 写作纪律（沿用本项目已确立的）

1. **每个数字标 n 与口径**；两个口径**永远并列**（结论依赖口径这件事本身就是 C4）；
2. **"读不到"不等于"零"**；缺失字段如实呈现；
3. **负面结果与边界主动写**（§2 末六条）；
4. **预登记与修订记录一并进 artifact**（含对自己不利的两处）；
5. **双重用途一节照 `2026-10-01-dual-use-and-harm-assessment.md` 写**：范围声明 + 危害形态 + 红线；
6. **不得把"原语"写成"APT"**——过度声明是本工作最现实的风险（见评估 §4 的 H4/H5）。
