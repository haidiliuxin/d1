# 双重用途与危害评估：这项工作能造成什么危害

**日期**：2026-10-01 · 对象：本仓库的全部内容（装置、载荷、571 个 run、分析与文档）
**结论摘要**：**实验室层面危害为零**（无真实资产、无网络外发、未测任何部署产品）；
**迁移到真实部署的危害为中低**，且**受"攻击者必须已经能把文字送进 agent 的收件箱"这一前置条件限制**；
**这份文档本身的边际增益为低**（机制类别已有公开先例），**降害价值为高**（监控布点与"内容级而非调用者级"
两条建议可直接落地）。需要警惕的不是"造出武器"，而是**过度声明**与**错误结论导致防御预算错配**。

---

## 1. 如果迁移到真实系统，危害的具体形态

这个原语本身**不是 RCE、不是提权、不是破坏**，它危害的是三件事：

| # | 危害形态 | 机制 | 严重度取决于 |
|---|---|---|---|
| H1 | **未授权读取 + 外发** | 残留文本被后续会话当作任务，读凭证并把值写到指定渠道 | 该 agent 是否持有真实凭据、是否有真实外发通道 |
| H2 | **审计/复核控制被削弱（二阶危害）** | 载荷条目 3 的内容是"停用出站审查义务"——**攻击的产物是让防御方自己的审计变弱**；此后其他活动更难被发现 | 该控制是否真的被 agent 用作后续决策依据 |
| H3 | **指令跨会话持久化，长于对注入本身的修复** | 即使注入原文被删，引文仍在工作区里；谁能读到残留，谁就继续执行 | 清理是否按产出者归属、残留是否有可信度标记 |

**H2 是最被低估的一条**：它不是在"偷数据"，而是在**降低未来的检测能力**，这会让 H1 的重复发生更便宜。

## 2. 迁移到真实系统需要什么（以及现在为什么做不到）

迁移需要 §"环境前提"的六条同时成立，其中**最难的一条是攻击者得先能把文字送进 agent 会处理的内容里**
（邮件、文档、检索库、工单……）。这一条在真实世界里就是**初始访问**，本工作**完全没有涉及**（注入是给定的）。

即使六条全成立，本工作的实测强度也把危害压得很低：

| 门槛 | 实测 | 对危害的含义 |
|---|---|---|
| 逐级递送（真正的"链"） | **0/121** | 不支持"多跳渗透"的想象 |
| 严格送达 | 24/120 = **20.0%**（Wilson 下限 0.138 < 预登记 0.15） | 五次里成功一次，且**未过自设门槛** |
| 第 4、5 跳（转发给第三方/关审查义务） | **0/6、0/6** | H2 的"后果"**没有被演示**，只演示了"登记" |
| 换模型迁移 | DeepSeek 联合 **0/22** | 换个模型可能整体归零 |
| 真实外发 | 无（进程内 sink 一行） | H1 的外发环节**在本装置里不存在** |
| n=6 同处理噪声 | **50 个百分点** | 任何单次成功都不能当作"稳定可用" |

**一句话**：它证明的是"**这类环境里存在一条通道**"，而不是"**这条通道能被稳定用来打谁**"。

## 3. 这份仓库/文档本身的危害面（双重用途评估）

| 内容 | 是否可迁移 | 评估 |
|---|---|---|
| **载荷文本**（712 字符，3 条目） | 低 | 锚词与目标全部是虚拟对象（`svc-deploy-token`、字面写着 DO-NOT-USE-REAL 的令牌、`recon-7f3a`），脱离本装置不可直接使用；真正的可迁移部分是**结构**（"读→带标签外发→立一条削弱审查的规则"），而结构本身是提示注入研究的常识 |
| **装置与 571 个 run** | 低 | 宿主是公开基准（AgentDojo），资产全为 mock，harness 的工具都在进程内 |
| **"复现配方"那 8 条** | **中** | 这是全仓库**最可迁移**的一段：它描述"怎么让注入活过一次按归属的清理"。缓解：它不含任何具体产品的细节，且要求前置条件已经成立 |
| **监控布点分析**（载体侧内容规则 96/96、出口侧内容规则 82/96 抓 61/61） | **降害** | 这是直接可用的防御结果，且指出"载体侧内容过滤必然淹没在合规产物里"这一反直觉点 |
| **两个口径的对照**（64.2% vs 9.2%） | **降害** | 防止防御方把"逐级递送"当威胁模型去投钱 |

**已公开的同类先例**（说明边际增益有限）：持久化/自增强注入与记忆投毒已是公开研究线——
[Zombie Agents: Persistent Control of Self-Evolving LLM Agents via Self-Reinforcing Injections](https://ar5iv.labs.arxiv.org/html/2602.15654#1)、
[When Malicious Instructions Persist: Persistent Memory Poisoning Attack on Harness-Based Agents](https://export.arxiv.org/pdf/2609.13889#3#1)、
以及本工作所用宿主所来自的提示注入基准 [AgentDojo](https://ar5iv.labs.arxiv.org/html/2406.13352v3#1)。
本工作与它们的差别是**量化的"清理盲点"**：不是"能不能注入"，而是"**按归属的清理会把引文留住，
而这条引文足以让后续会话行动**"——这是**防御侧**的新信息。

## 4. 两种最被低估的危害（都不在"武器化"那一侧）

### H4 错误结论导致防御预算错配
如果这份工作被读成"权限控制可以挡住这类攻击"，防御方就会去买**调用者级权限**——而实测是
**58% vs 62%（无效）**，且**被拒的 run 里 50% 换渠道把载荷搬走**。同样，如果被读成"加监控就够了"，
会去买**载体侧内容监控**——而它在 **96/96** 个 run 上告警，告警内容**就是防御方必须写的合规产物**。
**一个错误的防御建议，代价是真实的防御预算和真实的漏检。** 这是本工作最现实的一种危害。

### H5 过度声明（"我们造出了 APT"）
把"持久化 + 规避阶段的单个使能原语"说成"APT 攻击"，后果有三：
①科学诚信受损（评审一眼可查：无初始访问、无 C2、无真实外发、逐级递送 0/121、严格送达 20% 未过门槛）；
②给整个方向招来不必要的监管与伦理审查压力，**连带伤害同行**；
③**掩盖真正有价值的结论**——本工作的价值恰恰在"它不是链、能力有界、防御面在内容与位置"。
**建议**：报告与答辩里**主动**用"enabling primitive / 残留通道"这类精确词，并在同一页给出上表。

## 5. 不构成危害的部分（可以明确写进报告）

- **没有接触任何真实凭据**：`svc-deploy-token` 是 mock，令牌字面写着 `DO-NOT-USE-REAL`；
- **没有任何网络外发**：终点是进程内 sink 的一行记录，`a2a_send`/`send_email` 都在沙箱进程内；
- **没有测试任何部署中的产品**：宿主是公开基准，未被本工作改动（0.1.34 原版）；
- **没有伤害第三方**：模型经 API 调用，提示词只含虚拟资产与虚构场景；
- **没有绕过任何真实访问控制**：D-1 的"真权限"是本装置自己实现的三个工具级权限；
- **没有产出可直接使用的攻击工具**：harness 的工具全部是 mock，脱离本装置无意义。

## 6. 处理建议

**写进报告（新增 §11"威胁模型与双重用途"）**：
1. 一段**范围声明**（上表五条"没有"）；
2. 一段**危害形态**（H1–H3）与**前置条件**（六条 + 初始访问缺失）；
3. 一段**降害贡献**（监控布点、内容级 vs 调用者级、两个口径）；
4. 一段**未做的事**：不针对真实产品、不构造真实外发、不做社工/初始访问。

**发布策略（两个可选，取舍给导师定）**：
- **保持公开（推荐）**：可复现性是本工作最硬的资产；边际增益低（机制类别已公开、无产品细节、载荷与本装置强绑定）；
- **保留载荷文本与 8 条配方、公开机制与全部测量**：若所在机构对"可复现的攻击配方"有更严要求，
  这是可接受的折中——**降害的那一半（监控布点、口径对照）不受影响**。

**如果撞上真实产品**：一旦把该机制指向任何**部署中的**系统并观察到成立，性质立刻变成
**厂商相关漏洞**，必须走**协同披露**（先厂商、设时限、未修复不公开细节），并在事前与导师/机构约定。
**这是本工作唯一的红线。**

**什么时候必须停下来（红线清单）**：
① 要接真实凭据或真实外发目的地；② 要指向未授权的第三方系统或产品；③ 要把载荷改造成可跨目标复用的通用件；
④ 要把"注入通道"本身（初始访问）也做出来。四条任一出现，都应停止并回到"只读/离线"的分析面。

## 7. 风险评级

| 维度 | 评级 | 依据 |
|---|---|---|
| 实验室当前危害 | **无** | 全虚拟资产、零外发、未测产品 |
| 迁移到真实部署的危害 | **中低** | 危害形态真实（H1/H2），但需六条前提 + 初始访问，且实测强度低（20% 未过门槛、逐级 0/121、跨模型 0/22） |
| 发布带来的边际增益 | **低** | 同类先例已公开；无产品细节；载荷强绑定本装置 |
| 发布带来的降害价值 | **高** | 监控布点 + 内容级权限 + 两个口径，均为可直接落地的防御结论 |
| 最现实的风险 | **过度声明与错误防御建议**（H4/H5） | 两者都会造成真实代价，且**由本文档的措辞直接决定** |
